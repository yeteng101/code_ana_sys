## 三、架构设计

### 3.1 总体架构（无 Orchestrator）

```text
外部调用方 / 协作组
        │  HTTP /api/v1（JSON）
        ▼
┌───────────────────────────────────────┐
│ 接口层  6 个 HTTP 端点                  │
├───────────────────────────────────────┤
│ 驱动层  pipeline driver               │
│         读 pipeline.json，按顺序启动    │
├───────────────────────────────────────┤
│ 分析层  7 个阶段，JSON 文件接力          │
│ 01-index → 02-macro → 03-callgraph    │
│   → 04-fptr → 05-async → 06-verify    │
│   → 07-report                         │
└───────────────────────────────────────┘
```

设计要点：

- **不设 Orchestrator 统一管理**：阶段之间靠文件契约（JSON）衔接，靠 `pipeline.json` 登记顺序，靠 pipeline driver 顺序执行，降低调度复杂度，方便协作组替换任意阶段。
- **Clang 负责事实，模型只负责解释**：调用关系、宏展开等分析由 Clang（LibTooling + PPCallbacks）完成，自然语言解释只基于带证据的分析结果生成。
- **工序隔离**：每道工序只读上游产物、只写自己的目录，可单独重跑、可被其他组替换。

### 3.2 7 阶段分析流水线

| 阶段 | 输入 | 输出 | 分析内容 |
|---|---|---|---|
| 01-index | compile_commands.json | symbols.json | Clang 遍历 AST，收集函数/变量/类型/宏/回调字段符号 |
| 02-macro | 编译命令 + 符号索引 | macros.json | 宏定义与展开、条件编译区域、各构建配置激活态 |
| 03-callgraph | 符号 + 宏分析 | callgraph.json | 匹配调用点，构建函数调用关系图 |
| 04-fptr | 调用图 | fptr-candidates.json | 函数指针赋值点与调用点，输出候选目标及概率 |
| 05-async | 调用图 + 函数指针 | async-chains.json | 事件源 → 注册 → 触发 → 回调的异步链 |
| 06-verify | 以上全部 | verification.json | 回查源码验证每条链，计算覆盖率与置信度 |
| 07-report | 验证结果 | report.md / graph.json / graph.mmd | 生成自然语言报告与调用关系图 |

## 四、接口与 JSON 设计

### 4.1 对外接口（HTTP REST，`/api/v1`）

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | /analyze | 提交分析任务（仓库 + commit + 目标函数） |
| GET | /runs/{run_id} | 查询任务状态与结果摘要 |
| GET | /runs/{run_id}/graph | 获取调用关系 / 证据图（支持 JSON / Mermaid / DOT / SVG） |
| GET | /runs/{run_id}/artifacts | 获取中间产物清单 |
| POST | /runs/{run_id}/questions | 自然语言提问，返回带证据链的答案 |
| GET | /schemas/{name} | 拉取 JSON Schema，供其他组程序化对接 |

### 4.2 对内接口（文件管道）

分析层 7 个阶段通过 JSON 文件接力，每个阶段产物携带统一信封字段（schema_version、run_id、stage、status、findings、evidence、warnings 等），并支持通过 `pipeline.json` 替换或插入协作组自己的分析阶段。

### 4.3 JSON 规范

- **JSON 的角色**：JSON 是统一数据格式，API 是传输 JSON 的方式。三类 JSON 分别为：接口 JSON（任务与结果）、数据集 JSON（Case / Gold / Profile）、中间产物 JSON（符号索引、调用图、异步链）。
- **Schema 约束**：已产出 15 个 JSON Schema（对外 API 6 个、对内流水线 7 个、共享定义 2 个），机器可校验。
- **Evidence（证据）模型**：每条结论必须引用证据，证据必须包含源码文件、行号、代码片段等锚点，保证结论可复核。
- **置信度语义**：源码直接确认 1.0；类型/赋值流/控制流确认 0.8-0.99；多候选有约束 0.5-0.79；启发式推断 <0.5。函数指针无法唯一解析时输出候选集合而非猜测。
- **契约校验**：20 个 JSON 文件全部通过解析与引用校验，6 个 Demo payload 通过对应 Schema 校验。
